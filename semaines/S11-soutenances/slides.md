## Ce que vous savez faire maintenant

* Expliquer ce qui se passe entre un clic et l'affichage : HTTP, requête, réponse
* Construire une interface sémantique, responsive, interactive
* Écrire un serveur qui valide, protège, et parle à une base de données
* Structurer une application comme le font les frameworks
* Défendre votre code devant quelqu'un qui pose des questions

Et surtout : vous l'avez fait **sans framework**. Vous savez ce qu'il y a dessous.

---

## Les quatre règles, pour toujours

1. Échapper toute sortie
2. Hacher les mots de passe
3. Vérifier l'accès côté serveur, et la propriété de la ressource
4. Préparer toute requête

Elles valent en PHP, en Python, en JavaScript, en Java. Dans **tous** les frameworks.

---

## Et après ?

| Si vous aimez... | Regardez... |
|---|---|
| Le serveur, PHP | Laravel ou Symfony : vous reconnaîtrez le routeur, les contrôleurs, les templates, les repositories |
| Le JavaScript | TypeScript, puis React, Vue ou Svelte |
| Le serveur, autre langage | Django ou FastAPI (Python), Express (Node), Spring (Java) |
| La sécurité | OWASP Top 10, les challenges type CTF web |
| Mettre en ligne | Un hébergement PHP, puis Docker |

Vous apprendrez vite : vous connaissez déjà les fondations.
